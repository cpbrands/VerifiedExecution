# VE-001 v0.1 Comparison Against Validated Action Identity Requirements

**Date:** 2026-08-20  
**Source:** VE-001 v0.1  
**Validation baseline:** KERNEL_VALIDATION through v0.10

## Result

**SUBSTANTIVE GAP CONFIRMED.**

### Compatible foundations

VE-001 v0.1 already correctly establishes that:

- Action is canonical and immutable.
- Action existence does not imply authorization or execution.
- `action_id` is historical identity.
- Same payload does not imply the same Action.
- Idempotency identity differs from Action identity.
- Duplicate detection must not rely solely on payload equality.
- Retries do not automatically create new Actions.
- Material semantic mutation requires a new Action.
- Canonical hashing is recognized as a future requirement.

### Normative gaps

1. **No required `action_digest`.** `action_id` is the only normative Action identity.
2. **No `instance_digest`.** There is no cryptographic binding between Action occurrence and exact Action content.
3. **Monolithic semantic field model.** Section 12 labels `action_id`, `created_at`, `initiator`, `authority_context`, `target`, `operation`, `arguments`, and `scope` as semantic content.
4. **Initiator is over-specified.** Proposer identity is usually governance/provenance, not intrinsic effect semantics.
5. **Authority context is over-specified.** Authority must be established independently through Claims and Trust Context.
6. **Universal `scope` is over-specified.** Applicability can be determined over canonical schema-defined Action fields without a `Scope` primitive.
7. **`created_at` is misclassified.** Its stated evidentiary meaning is occurrence-level unless time explicitly constrains execution.
8. **No content-addressed schema identity.** Schema/versioning is discussed, but no normative schema digest is required.
9. **Hashing is optional.** Section 53 says implementations MAY hash Action semantics; validated architecture requires cryptographic content identity.
10. **VE-004 dependency.** Receipt identity cannot be finalized until VE-001 defines `action_id`, `action_digest`, and `instance_digest`.
